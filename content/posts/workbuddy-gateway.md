手上有几个 WorkBuddy 账号，额度分散在各处，官方客户端一次只能用一个，挺烦。

想的是：在任何支持 OpenAI 协议的编辑器里都能直接用，谁管你额度在哪个账号上。

本来是跑在电脑上的，但我不想为了用个接口天天开着电脑。于是把它塞进手机。

> **写在前面**：手机上跑的这个版本还在折腾中。下面的思路和踩过的坑是真的，KernelSU 模块那一版还没正经测过，具体数字什么的就先别信。想到哪写到哪，主要留个记录。

## 大概是个什么形状

```
客户端(任意 OpenAI 兼容)  ──►  手机上的 Go 网关  ──►  WorkBuddy 上游
                                    │
                            账号池 / 冷却 / 会话粘性
```

网关本体是个 Go 二进制，监听 `127.0.0.1:7863`，客户端填个 Base URL 就能用。

两种装法的打算：APK 给普通安卓（无需 root），KernelSU 模块给想开机自启的人。前者能跑，后者还在折腾。

## 三个真正花时间的点

### 账号池不能只是轮询

最初就是简单轮询，结果很糟：上一个请求刚用完账号 A，下一个换到 B，B 又不认识刚才的对话。多轮对话直接断片。

改成了**会话粘性**：拿对话指纹绑到具体账号上，TTL 30 分钟。同一段对话永远落在同一个账号上，换话题才可能漂移。

```go
// 伪代码
func (s *Sticky) Pick(fingerprint string) (*Account, bool) {
    if a, ok := s.get(fingerprint); ok {
        return a, true
    }
    a := s.pool.Next()
    s.set(fingerprint, a, 30*time.Minute)
    return a, false
}
```

### 冷却要分错误码

所有错误都退避 60 秒是偷懒。实际上：

- **402**（额度耗尽）→ 压到次日，中间不用试
- **429**（限流）→ 指数退避，10 秒起翻倍
- **404**（模型不存在）→ 固定 60 秒，通常就是上游模型列表变了

按错误码分策略之后，无效重试少了一大截，账号也不会因为一次限流被误伤半天。

### 冻结诊断

手机上跑后台服务最怕的是「看着在跑，其实早就僵了」。进程活着，goroutine 卡住，请求进来没反应。

加了个心跳。超过 90 秒没打点就判定冻结，界面红字告警。上线之后才第一次看清问题是「网络慢」还是「真的死了」。

## 安卓上跑 Go 服务的几个坑

**必须用 CGO。** 纯 Go 静态编译 DNS 解析会失败（安卓没有 `resolv.conf`）。加 `CGO_ENABLED=1` 用 NDK 编译，走 bionic 解析器就正常了：

```bash
GOOS=android GOARCH=arm64 CGO_ENABLED=1 \
  CC=$NDK/aarch64-linux-android26-clang \
  go build -trimpath -ldflags "-s -w" -o libwb2api.so ./cmd/server
```

产物虽然叫 `.so`，其实是可执行文件，放 `jniLibs/` 里由 App 直接 `exec`。这样绕开 `data` 分区不可执行的限制。

**省电要看唤醒锁，不是 CPU。** 早期版本拿 `PARTIAL_WAKE_LOCK`，一晚上掉 20% 电。改成前台服务之后好多了。

**32 位机器还很多。** `GOARM=7` 单独编一份，按 ABI 分目录。

## 多模态是个麻烦事

文本转发很直接，视频音频就麻烦——上游接口不认 `video_url`，也不认 `input_audio`。

最后的做法是本地预处理：

- **视频**：事件引导抽帧（场景切换处多抽几张），转成 `image_url` 数组塞进消息
- **音频**：抽音轨转 16kHz WAV，本地跑 TFLite 识别声音事件，同时走上游 ASR 转文字

抽帧数量做成无极调节的滑杆。因为「抽 4 帧」和「抽 16 帧」在不同视频上差别很大，固定值总有一头不合适。
